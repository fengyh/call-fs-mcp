\section{简介}
本文档以 \bf{MCP（Model Context Protocol）}接口的使用为核心，介绍在 \bf{snowy} 快速开发框架的基础上，开发 \bf{Web 应用程序（WEBAPP）}与 \bf{FactorySimulation（FS）}仿真引擎集成的总体方法、开发步骤和重点事项。文档面向的读者是：需要在 snowy 框架上开发 FS 仿真控制功能的云端后端工程师、前端工程师以及测试人员。

FS 仿真引擎通过内置的 MCP Server 对外提供模型加载、仿真运行控制、状态与结果查询、参数表读写、动画画面获取等能力。WEBAPP 不需要直接操作仿真引擎的内部 API，只需按照 MCP 协议以 \bf{HTTP JSON-RPC 2.0} 的方式调用 MCP 工具，即可完成一次仿真任务的完整生命周期管理。

本文的总体调用链如下：
\begin{lstlisting}
Vue 前端 (snowy-admin-web)
   |   REST /fscloud/sim/*  (axios)
   v
云端后端 (snowy-plugin-fscloud 插件模块)
   |   MCP tools/call  (HTTP JSON-RPC 2.0, X-API-Key 鉴权)
   v
FS 仿真引擎 MCP Server  (默认 http://127.0.0.1:8081/mcp)
   |   引擎内部仿真 API
   v
FactorySimulation 仿真模型实例
\end{lstlisting}\vspace{-30pt}
\par 仿真引擎运行期间的状态、进度、控制台日志以及浏览器动画帧，通过 \bf{MQTT} 实时消息通道推送给后端和前端，与 MCP 的请求-响应式调用形成互补，共同构成 WEBAPP 与 FS 集成的完整数据通路。

\subsection{MCP 介绍}
\bf{MCP（Model Context Protocol，模型上下文协议）}是由 Anthropic 于 2024 年底提出并开源的开放标准协议，用于标准化\it{应用程序/大语言模型}与\it{外部数据源、工具}之间的交互方式。它解决了传统上每个应用都要为每种外部能力单独实现一套对接协议的问题，把\it{能力暴露}与\it{能力调用}统一为一种标准形态。

MCP 体系中有三个核心角色：
\begin{enumerate}[label=\arabic*)]
	\item \bf{Host（宿主）}：发起连接的应用程序，例如 AI 助手、IDE 或本文中的云端后端。
	\item \bf{Client（客户端）}：在 Host 内部运行，负责与 Server 建立连接、交换消息。
	\item \bf{Server（服务端）}：暴露能力的一方，把内部功能封装为标准化的\it{能力原语}。
\end{enumerate}
MCP 定义了三种能力原语：
\begin{enumerate}[label=\arabic*)]
	\item \bf{Tools（工具）}：可被调用的函数，有名称、参数 schema（JSON Schema）和返回结果，是\it{请求-响应}式的，例如“启动仿真”“查询状态”。
	\item \bf{Resources（资源）}：可被读取的数据，例如文件内容、数据库记录。
	\item \bf{Prompts（提示词）}：可被复用的提示模板，主要服务于 AI 场景。
\end{enumerate}
MCP 支持多种传输方式：\it{stdio}（本地子进程通信）、\it{HTTP}（基于 JSON-RPC 2.0 的 Streamable HTTP）、\it{SSE}（Server-Sent Events）等。本文使用的 FS 仿真控制接口采用\bf{HTTP JSON-RPC 2.0} 传输方式。

需要特别说明的是：\bf{MCP 并不只服务于 AI 助手场景}。它本质上是“结构化工具调用”的标准协议。在本文的集成方案中，MCP Server 就是 FS 仿真引擎的能力网关，云端后端把它当作一个普通的远程服务调用即可，不涉及任何大语言模型（LLM）。这样 WEBAPP 获得了三个好处：一是\it{工具定义标准化}，通过 \texttt{tools/list} 即可发现仿真引擎的全部能力及参数；二是\it{调用格式统一}，所有仿真操作都走同一种 JSON-RPC 请求/响应结构；三是\it{职责清晰}，仿真引擎的复杂内部逻辑被隔离在 MCP Server 内部，WEBAPP 无需关心。

\subsection{FS 仿真控制 MCP 接口介绍}
\bf{FactorySimulation（FS）}是面向工厂物流与生产系统的仿真引擎。FS 的 MCP Server 运行在仿真引擎进程中，默认端点地址为 \texttt{http://127.0.0.1:8081/mcp}（生产环境可按部署修改），鉴权方式为请求头 \texttt{X-API-Key}，请求体为 JSON-RPC 2.0 格式。会话初始化先发送 \texttt{initialize}，再发送 \texttt{notifications/initialized}，之后通过 \texttt{tools/list} 查询工具清单、通过 \texttt{tools/call} 调用具体工具。

\subsubsection{统一业务响应格式}
所有仿真工具调用成功后的业务结果，存放在 MCP 响应的 \texttt{result.content[0].text} 字段中，是一个 JSON 字符串。该 JSON 采用统一的业务响应结构：
\begin{lstlisting}
{
  "success": true,          // 是否成功
  "code": "OK",             // 业务错误码
  "message": "success",     // 提示信息
  "data": { ... }           // 业务数据
}
\end{lstlisting}\vspace{-30pt}
常见业务错误码有：
\begin{itemize}
    \item\texttt{INVALID\_ARGUMENT}（参数非法）
    \item\texttt{MODEL\_FILE\_NOT\_FOUND}（模型文件不存在）
    \item\texttt{USER\_MODEL\_LIMIT\_EXCEEDED}（单用户模型数超限）
    \item\texttt{GLOBAL\_MODEL\_LIMIT\_EXCEEDED}（全局模型数超限）
    \item\texttt{GLOBAL\_RUNNING\_LIMIT\_EXCEEDED}（全局运行数超限）
    \item\texttt{MODEL\_NOT\_FOUND}（模型不存在）
    \item\texttt{INVALID\_STATE}（当前状态不允许该操作）
    \item\texttt{SIMULATION\_START\_FAILED} (仿真启动失败）
    \item\texttt{PARAMETER\_TABLE\_NOT\_FOUND} (参数表不存在)
    \item\texttt{RESULT\_NOT\_READY} (结果未就绪)
    \item\texttt{DATASET\_NOT\_FOUND} (数据集不存在)
    \item\texttt{INTERNAL\_ERROR} (内部错误)
\end{itemize}
    WEBAPP 后端解析出该 JSON 后，应将 \texttt{success/code/message/data} 原样（或按公司统一响应格式转换后）返回给前端。

\subsubsection{模型状态机}
FS 远程仿真模型的状态取值及常见流转如下：
\begin{lstlisting}
NOT_LOADED -> LOADED -> RUNNING -> PAUSED -> RUNNING -> FINISHED
RUNNING / PAUSED -> STOPPED -> LOADED (reset 后)
任何启动异常 -> FAILED
\end{lstlisting}\vspace{-30pt}
\begin{itemize}
	\item \texttt{loadRemoteSimulationModel} 成功后状态为 \texttt{LOADED}。
	\item \texttt{startRemoteSimulation} 成功后状态为 \texttt{RUNNING}。
	\item 仿真自然结束后状态为 \texttt{FINISHED}，可读取结果。
	\item \texttt{resetRemoteSimulation} 只允许在非运行/非暂停状态调用，成功后回到 \texttt{LOADED}。
\end{itemize}
同时存在资源配额限制：\bf{单用户最多加载 1 个模型，全局最多加载 10 个模型，全局最多 5 个模型同时运行}。

\subsubsection{MQTT 实时消息通道}
仿真运行期间，引擎通过内置 MQTT Broker 发布实时消息，主题结构为 \texttt{factory/sim/\{username\}/\{modelId\}/...}：
\begin{itemize}
	\item \texttt{status}：状态事件（如 \texttt{simulationStart}、\texttt{resultReady}），携带状态、仿真时间等；
	\item \texttt{progress}：运行进度与仿真时间；
	\item \texttt{console}：控制台日志（级别、内容、序号）；
	\item \texttt{events}：可开关的 MU 事件批次，按 200～500ms 的现实时间窗口聚合发布；批次内事件不采样、不丢弃，并按 `sequence` 排序。超过 500 条时通过 `chunkIndex/chunkCount` 拆包。
	\item \texttt{animation/layers}、\texttt{animation/state}、\texttt{animation/frameMeta}：动画层级目录、推流状态、帧元数据；
	\item \texttt{animation/\{layerId\}/frame}：原始 JPEG 二进制动画帧（默认 5 FPS，最高 10 FPS）；
	\item \texttt{animation/\{layerId\}/objects}：结构化对象帧（JSON，用于数字孪生渲染\footnote{\bf{数字孪生渲染}: 此方法是将仿真模型中的对象（包括MU）的位置信息，通过MQTT实时发布，与外部数字孪生系统中的对象通过id或名称映射，进行同步渲染。模型较大时，数据量非常大，不推荐此方法，而应该采用通过`getRemoteSimulationObjectPositionSnapshotPage`取一次对象位置快照，再通过`getRemoteSimulationEvents`批量获取指定时间窗内mu事件（相当于物位信号的数据采集），进行数字孪生的驱动和触发补间动画。 }）。
\end{itemize}
其中动画帧是 Qos 0\footnote{\bf{Qos 0}: 即最多只发送一次，不保证消息一定会送达, MQTT客户端未订阅就错过了。}、非 Retain 的二进制消息，不能按 UTF-8/JSON 解析；一般WEB应用开发中，状态通常需要双端(即前端和后端)订阅\footnote{\bf{双端订阅}：前端和后端同时订阅，WEB应用在多租户场景时，会有同时多个模型加载、多个模型在仿真的情况，前端显示模型库时希望看到哪些模型被其它用户加载和仿真。因此后端需要订阅这些状态消息，在内存中进行当前加载模型的状态维护，并落库备查。}，进度、控制台消息由前端订阅，动画帧由前端通过 WebSocket 桥接订阅。

\subsection{基于snowy框架开发与FS仿真集成的WEBAP的步骤}
\bf{snowy} 是国内开源的前后端分离快速开发平台，采用 SpringBoot 3 + MyBatis-Plus + Sa-Token + AntDesignVue 3 + Vite 等技术栈，提供代码生成、权限管理（含 Sa-Token 鉴权）、国密加密等开箱即用的能力。FS 集成业务放在独立的业务插件模块 \texttt{snowy-plugin-fscloud} 中实现，WEBAPP 的启动模块 \texttt{snowy-web-app} 只负责启动与数据库/Web 配置。总体开发步骤如下：

\begin{enumerate}[label=\arabic*)]
	\item \bf{工程搭建与环境准备}\label{sec:brief-step1}
	\begin{itemize}
		\item 拉取 \href{https://gitee.com/xiaonuobase/snowy}{snowy 框架代码}，创建业务插件模块 \texttt{snowy-plugin-fscloud}，并在 \texttt{snowy-web-app} 中引入该模块依赖\footnote{\bf{创建业务插件模块并在webApp中引入}：创建独立的业务插件模块，便于代码组织和复用。方法见\href{https://xiaonuo.vip/doc?catalogueId=1574674577108783105&menuId=1574678028987420674&lineIndex=1}{框架后端开发的“插件规范”}}。
		\item 准备 MySQL 8.0 数据库（本项目约定库名 \texttt{fp\_mysql}）与 Redis，导入框架初始化脚本创建数据库表。\\框架初始化脚本位于：\texttt{snowy-web-app/src/main/resources/\_sql/snowy\_mysql.sql}。
        \item 按\ref{appendix:database-ddl}章节所述DDL，创建3个表，用于持久化模型库、仿真参数快照和仿真结果快照。
		\item 运行 FS 仿真引擎（\texttt{fs-mcp} 版，可作桌面端也可作服务端），确认 MCP 端点可用\footnote{\bf{确认 MCP 端点可用}: 使用Cherry Studio或Reasonix等工具添加MCP(`http://127.0.0.1:8081/mcp`)，看是否可以浏览到CP工具。具体操作见附录“CherryStudio辅助调试”\ref{appendix:cherry-studio}}、确认 MQTT Broker（FS 内置）正常工作\footnote{\bf{确认MQTT Broker正常工作}: 使用MQTTX辅助工具，看是否可以正常建立连接，具体操作见附录“MQTTX辅助调试”\ref{appendix:mqttx}}。
	\end{itemize}
	\item \bf{配置 MCP 连接参数}
	通过 \texttt{@ConfigurationProperties} 定义 \texttt{McpProperties}\footnote{\bf{McpProperties位于}: snowy-plugin/snowy-plugin-fscloud/src/main/java/vip/xiaonuo/fscloud/config/McpProperties.java}，读取配置项 \texttt{fscloud.mcp.endpoint-url}（默认 \texttt{http://127.0.0.1:8081/mcp}）与 \texttt{fscloud.mcp.api-key}，生产环境可在 \texttt{application-prod.properties\footnote{\bf{生产环境配置文件位于}:snowy-web-app/src/main/resources/application-prod.properties}} 中覆盖。API Key 属于敏感信息，\bf{不应下发给前端}。
	\item \bf{封装 MCP 客户端服务（McpClientService）}\label{sec:brief-step3}
	在后端封装一个 \texttt{McpClientService\footnote{\bf{McpClientService位于}: snowy-plugin/snowy-plugin-fscloud/src/main/java/vip/xiaonuo/fscloud/modular/simulation/service/McpClientService.java}}，集中实现与 MCP Server 的通信，供所有 Controller 复用，避免重复实现 HTTP 通信逻辑。关键实现点：
	\begin{itemize}
		\item \texttt{call()}：发送 \texttt{initialize}、\texttt{tools/list} 等非工具类 JSON-RPC 方法\footnote{\bf{非工具类方法}: initialize - 校验初始化状态, tools/list - 让客户端拿到服务器支持的工具清单和参数 schema。本Demo不是AI Agent类的MCP调用，所以这两个步骤省略了。}；
		\item \texttt{callTool(toolName, args)}：构造 \texttt{tools/call} 请求，\texttt{params.name} 为工具名，\texttt{params.arguments} 为参数对象；
		\item HTTP 发送使用 \texttt{HttpURLConnection}，POST + \texttt{Content-Type: application/json} + 请求头 \texttt{X-API-Key}，建议连接超时 10s、读超时 60s；
		\item \texttt{unwrapResult()}：两层解析——先解析 MCP 响应取 \texttt{result.content[0].text}，再将该字符串解析为业务 JSON；
		\item 响应含 \texttt{error} 字段或连接异常时，抛出统一的 \texttt{McpServiceException}，由上层转为业务错误。
	\end{itemize}
	示例（启动仿真）：
	\begin{lstlisting}
// 构造 MCP tools/call 请求
JSONObject args = new JSONObject();
args.put("userId", userId);
args.put("modelId", modelId);args.put("showAnimation", showAnimation);
// callTool 内部: {jsonrpc, id, method: "tools/call",
//                params: {name: "startRemoteSimulation", arguments: args}}
return callTool("startRemoteSimulation", args);
	\end{lstlisting}\vspace{-30pt}
	\item \bf{建立模型库}\label{sec:brief-step4}
	\begin{itemize}
		\item 数据库建表 \texttt{fs\_model\_file}，保存模型元数据（名称、引擎版本、文件路径、\texttt{sim\_status}、\texttt{model\_id} 等），对应实体 \texttt{FsModelFile} 与 Service/Impl。
		\item 后端支持 \texttt{fs-cloud-plugin} 建模器插件\footnote{\bf{建模器插件}: 通过plugin上传模型只是可选的方法之一，它的好处是可以在fs建模器中调试好模型之后直接上传到云平台，并能同时上传模型截图作为封面。云平台也可以采用在浏览器上传.fs模型文件的方法建立模型库的方法。} 的登录，提供模型上传接口 \texttt{POST /fscloud/modelfile/upload}：文件落盘到静态目录，\texttt{.zfs} 压缩包解压，随后把元数据写入 \texttt{fs\_model\_file} 完成“上传、落盘、落库”。
		\item 开发前端模型库页面，展示模型列表，提供上传、加载、卸载操作。
	\end{itemize}
	\item \bf{开发仿真控制后端接口（SimController）}\label{sec:brief-step5}
	开发 \texttt{SimController}，对外暴露 \texttt{/fscloud/sim/*} 形式的 REST 接口（如 \texttt{loadModel}、\texttt{runModel}、\texttt{pauseModel}、\texttt{resumeModel}、\texttt{stopModel}、\texttt{resetModel}、\texttt{unloadModel}、\texttt{getLoadedModel}、\texttt{getResultSnapshot}、\texttt{getResultDatasetPage}、\texttt{getObjectPositionSnapshot}（对象位置快照）、\texttt{getSimulationEvents}（时间窗仿真事件）、参数表与动画相关接口），每个接口：
	\begin{itemize}
		\item 用 \texttt{@SaCheckPermission} 声明权限码，接入 snowy 的登录鉴权；
		\item 调用 \texttt{McpClientService} 对应的封装方法完成 MCP 调用；
		\item 维护内存态 \texttt{SimulationModelTrackingMap}：以 \texttt{userId/modelId} 记录当前加载的模型、状态、运行 ID，并把 MCP 返回的 \texttt{modelId} 写回数据库 \texttt{fs\_model\_file}；
		\item 通过定时任务 \texttt{SimulationSyncTask}（每 10s）调用 \texttt{listRemoteSimulationModels} 同步内存与数据库中的模型状态，支撑后端重启后的状态恢复。
	\end{itemize}
	\item \bf{开发前端页面}\label{sec:brief-step6}
	\begin{itemize}
		\item 用 \texttt{@/api/fscloud/fsSimApi.js} 统一封装对后端 \texttt{/fscloud/sim/*} 的 axios 调用；
		\item 开发仿真控制页：加载模型、启动、暂停、恢复、停止、重置、卸载按钮，状态卡片（\texttt{modelId}、\texttt{modelFileName}、\texttt{status}、\texttt{runId}、\texttt{simTime}、\texttt{message} 等），结果卡片（\texttt{totalOutput}、\texttt{throughputPerHour}、\texttt{currentWip} 等）；
		\item 用 Pinia 定义 \texttt{myModel.js} 状态 store，保存当前模型与仿真状态，并把 MCP 状态映射为前端本地状态机，按状态禁用/启用按钮；
		\item 开发模型库页、参数管理页（参数表展示、编辑、快照保存/加载）与事件回放页（时间轴数据分析）。
	\end{itemize}
	\item \bf{MQTT 实时对接}\label{sec:brief-step7}
	\begin{itemize}
		\item 后端：用 Paho（\texttt{org.eclipse.paho.client.mqttv3}）实现 \texttt{MqttClientService}，订阅主题 \texttt{factory/sim/+/+/+}，解析 topic 末段区分 \texttt{status/progress/console}，分别更新内存记录并同步写回 \texttt{fs\_model\_file.sim\_status}；
		\item 前端：用 \texttt{mqtt.js} 通过 WebSocket 连接 MQTT Broker（\texttt{ws://127.0.0.1:8083/mqtt}）；
		\item 订阅 \texttt{factory/sim/\{userId\}/\{modelId\}/+} 与 \texttt{.../animation/\#} 主题：JSON 消息按尾段类型分发，动画帧的二进制 payload 转为 \texttt{Blob('image/jpeg')} 显示在页面上，\texttt{animation/\{layerId\}/objects} 结构化对象帧存入 store 供实时事件分析。
	\end{itemize}
    \vspace{10pt} \bf{可订阅的 MQTT 主题如下，可参照 Demo 程序选择需要的，不一定全部订阅：}
    {\scriptsize
    \begin{verbatim}
    factory/sim/{username}/{modelId}/status                         模型状态
    factory/sim/{username}/{modelId}/progress                       仿真进度
    factory/sim/{username}/{modelId}/console                        FS控制台信息
    factory/sim/{username}/{modelId}/events                         MU事件：可用于实时驱动数字孪生，或保存到csv/nosql数据库做分析、回放

	\item \bf{参数表读写}\label{sec:brief-step8}
	\begin{itemize}
		\item 在 FS 建模器的模型中定义 \texttt{mcp}（或 \texttt{MCP}）表，把要开放给 Web 端读写参数表登记到该表第一列；后端只允许读写 \texttt{mcp} 表中列出的参数表；\\\tips{模型特有的“结果表”也可以放在MCP表的第一列，第二列填上WebApp约定的标识，例如“Out”表示这个表存放的是仿真的结果数据，这样前端就可以区分处理。}
		\item 参数管理页通过 \texttt{listRemoteSimulationParameterTables} 获取可读写表清单；
		\item 通过 \texttt{getRemoteSimulationParameterSnapshot} 读取表内容（\texttt{columns + rows}）并展示为表格；
		\item 修改后通过 \texttt{batchUpdateRemoteSimulationParameterTable}（\it{整批写回模型中的参数，这是全部替换模型中参数表的方法。可选 \texttt{bSaveModel}为true, 回写之后保存到 \texttt{.fs} 磁盘文件}）或 \texttt{updateRemoteSimulationParameterTable} / \texttt{updateRemoteSimulationParameterCells} 写回模型；
		\item 模型处于 \texttt{RUNNING/PAUSED} 时禁止写参数；新一轮仿真前先 \texttt{reset} 再 \texttt{start}；
		\item 参数快照可落库保存（表 \texttt{fs\_sim\_param\_snapshot}），供事后使用（不同版本的参数快照从数据库中读取，再回写到模型），或对比分析（分析不同版本参数对仿真结果的影响）。
	\end{itemize}
    \item \bf{参数快照与结果快照历史数据处理}\label{sec-history-data}
    \begin{itemize}
        \item \it{参数快照}（\texttt{fs\_sim\_param\_snapshot}）：参数快照按用途可分两种：一是只是单纯的参数管理，二是与结果快照成对落库以备将来做横向对比分析之用。两种都保存在同一个表中，前者只需要用modelFileId与模型库的模型关联，不需要runId字段。后者需要用modelFileId和runId表明是哪个模型的哪次仿真所使用的参数快照。参数快照在Demo中演示了行、列的修改，以及数值的修改方法。  
        \item \it{结果快照}（\texttt{fs\_sim\_result\_snapshot}）：结果快照在仿真停止（自然结束或手动中断停止）后才能通过MCP接口取出，落库是同样需要用modelFileId和runId表明是哪个模型的哪次仿真所使用的结果快照。
        \begin{itemize}
            \item 标准结果：仿真平台共性的统计和报告相关的数据，如设备利用率、每小时产量等。这部分的数据可在Demo程序的"仿真服务"-""历史数据""。
            \item 模型自定义结果: WebApp通常不会针对每个场景（模型）去深度挖掘特定的仿真输出数据，此时，可以由模型设计人员将需要的数据登记到存放结果的Table组件中，并将这些Table组件添加到\it{MCP表}的第一列，第二列填\it{Out}（或其它与WebApp约定的标识）。在WebApp中读取参数时，会将这些结果Table和参数Table一起读出，前端按\it{Out}标识将这些结果数据显示在适当的位置。
        \end{itemize}

    \item \bf{时间轴数据分析（事件回放）}\label{sec:brief-step9}
	利用\it{对象位置快照}(建议使用\bf{分页版}以便能适配大模型)、\it{仿真事件}两个 MCP 工具和 \texttt{objects} 实时对象订阅、\texttt{events}实时事件订阅，可以按仿真时间轴对仿真过程进行准实时（或回放）动画渲染开发数字孪生应用系统：
	\begin{itemize}
		\item 后端在 \texttt{SimController} 增加四个 REST 接口，分别透传 MCP 工具：
		\begin{itemize}
			\item \texttt{getObjectPositionSnapshot}（整体快照，指定时间）$\rightarrow$ \texttt{getRemoteSimulationObjectPositionSnapshot}（参数：\texttt{runId}、\texttt{layerId}、\texttt{simTime}）；
			\item \texttt{getObjectPositionSnapshotPage}（分页快照，推荐）$\rightarrow$ \texttt{getRemoteSimulationObjectPositionSnapshotPage}（参数：\texttt{runId}、\texttt{layerId}、\texttt{simTime}（\texttt{-1} 表示当前时刻）、\texttt{snapshotId}（首次传空串，后续原样回传防止分页内容漂移）、\texttt{entityKind}（\texttt{ALL}/\texttt{STATIC\_OBJECT}/\texttt{LAYER}/\texttt{MU}/\texttt{WAREHOUSE}/\texttt{STORAGE\_LOCATION}）、\texttt{offset}、\texttt{limit}（1--1000））；
			\item \texttt{getSimulationEvents} $\rightarrow$ \texttt{getRemoteSimulationEvents}（参数：\texttt{runId}、\texttt{startSimTime}、\texttt{duration}、\texttt{offset}、\texttt{limit}）；
			\item \texttt{setEventPublishing} $\rightarrow$ \texttt{setRemoteSimulationEventPublishing}（参数：\texttt{enabled}、\texttt{publishIntervalMs}，控制 FS 是否向 \texttt{events} 主题发布事件消息）。
		\end{itemize}
		前端在 \texttt{fsSimApi.js} 中封装对应 API；
		\item 开发事件回放页（\texttt{eventplayback/index.vue}）：用 \texttt{a-slider} 展示从 0 至总仿真时长的时间轴，用变量 \texttt{timeWindowCursor} 保存当前光标对应的时间点（仿真毫秒）并显示在 slider 上方；\bf{注意}：FS 引擎只保留约 5 分钟的对象位置快照，超出该时间范围的历史快照查询不到；
		\item 整体取位置快照（指定时间）：按光标位置调用 \texttt{getRemoteSimulationObjectPositionSnapshot}，获取该时刻的对象位置快照（对象 ID、类型、所在层、容器、相对位置等），用于还原仿真画面；
		\item 分页取位置快照（当前时间）：调用 \texttt{getRemoteSimulationObjectPositionSnapshotPage}，\texttt{simTime=-1} 立即捕获当前时刻，按 \texttt{offset/limit} 分页拉取完整对象快照（含静态对象坐标、Buffer/工位的 WIP、MU 所在容器与位置、仓库及货位 MU 清单等），\texttt{snapshotId} 原样回传防止仿真运行时分页内容漂移；
		\item 步进播放/回退：调用 \texttt{getRemoteSimulationEvents} 按 10 秒窗口（\texttt{duration=10000}）获取仿真事件（对象进入/离开工站等）；步进播放时光标后移 10 秒（\texttt{timeWindowCursor += 10000}），步进回退时光标前移 10 秒；
		\item 实时事件订阅（\texttt{events} 驱动）：前端先调用 \texttt{setEventPublishing}（\texttt{enabled=true, publishIntervalMs=500}）让 FS 开始发布事件，再自建 MQTT 连接订阅 \texttt{factory/sim/\{username\}/\{modelId\}/events}，将接收到的消息保存到 store（\texttt{myModel.events}），最多保存 100 条用于分析，之后不再保存；收到消息时按 \texttt{runId} 过滤，只保留当前运行的事件；"停止实时订阅"时调用 \texttt{setEventPublishing}（\texttt{enabled=false}）让 FS 停止发布，并断开 MQTT 连接；
		\item \bf{说明}：demo 不使用 \texttt{animation/\{layerId\}/objects} 主题——模型较大时该主题数据量比 JPEG 图片流还大，改为 \texttt{events} 事件驱动订阅，配合对象位置快照查询即可支撑数字孪生渲染。
	\end{itemize}

	\begin{itemize}
		\item \texttt{McpClientTest.java}：独立运行的端到端冒烟测试（\texttt{main} 方法），按 \texttt{initialize → tools/list → load → start → 轮询状态 → stop → 结果快照 → 分页 → reset → unload} 的顺序验证 MCP 全流程，可作为联调参考与回归用例；
