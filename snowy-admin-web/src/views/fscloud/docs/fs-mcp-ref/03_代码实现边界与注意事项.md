# 代码实现边界与注意事项

日期：2026-06-16

## 1. 这次实现和 AI 助手没有关系

本轮新增的是 MCP 工具和远程仿真管理器，不是 AI 助手。

代码没有做：

- 不创建 AI Agent
- 不调用 LLM
- 不接知识库
- 不做自然语言解析
- 不把模型控制委托给 AI

云端后端调用的是明确的 MCP 工具名，例如：

```text
startRemoteSimulation
pauseRemoteSimulation
getRemoteSimulationStatus
```

这些工具内部直接调用 FactorySimulation 的仿真 API。

## 2. 和旧 SimulationTools 的区别

当前已有 `SimulationTools` 更偏向 UI 当前模型：

- 依赖 `SimulationMainAPP.mainFrame`
- 读取当前打开的模型 tab
- 返回自然语言文本

本轮新增 `RemoteSimulationTools` 不再依赖“当前选中的 UI 模型”，而是由远程 session 驱动：

- 由 `RemoteSimulationManager` 自己加载模型文件
- 每个用户维护自己的远程 session
- 返回统一 JSON 字符串
- 适合云端后端解析
- `loadRemoteSimulationModel.loadInUI=false` 时为纯引擎模式
- `loadRemoteSimulationModel.loadInUI=true` 时把同一个远程模型挂载到桌面 UI tab

## 3. 模型加载策略

加载入口：

```java
RemoteSimulationManager.loadModel(String userId, String recordId, String modelFileName, boolean loadInUI)
```

内部流程：

1. 校验 `userId`、`recordId` 和 `modelFileName`。
2. 检查该用户是否已经加载模型。
3. 检查全局模型数量是否超过 10。
4. 按传入路径解析模型文件。
5. 创建 `SimulationModel`。
6. 调用 `ModelUtil.openModel(modelFile, model, modelFileVersion -> true)`。
7. 成功后创建 `RemoteSimulationSession`，保存 `userId`、后端模型库 `recordId` 和引擎实例 `modelId`。
8. 注册远程状态监听器和控制台文档监听器。
9. `loadInUI=true` 时创建 `ModelTabPanel`，并组合转发 UI 与 MCP 仿真监听事件。
10. 写入 `sessionByUser` 和 `sessionByModel`。

当前路径策略：

- 允许传绝对路径，适合云端后端上传模型后把引擎服务器上的真实路径传给 MCP。
- 允许传相对路径；相对路径只按 MCP Server 当前工作目录解析。
- 不再扫描 `help/examples`、`models`、`model` 等兜底目录。
- 当前 MVP 不在 MCP 工具层做目录白名单限制；生产环境建议由后端上传/存储模块控制路径来源和权限。

## 4. 内存管理策略

当前 MVP 只做内存管理：

- 进程重启后 session 全部丢失。
- 不做数据库恢复。
- 不做历史 run 查询。
- `runId` 只代表当前 session 最近一次启动。

限制：

```text
单用户最多加载 1 个模型
全局最多加载 10 个模型
全局最多运行 5 个模型
```

卸载模型时：

- 如果模型正在运行或暂停，会先 stop。
- 从 `sessionByUser` 移除。
- 从 `sessionByModel` 移除。
- 从 `SimulationModel.modelMap` 移除。

加载失败时：

- 如果已经创建 `SimulationModel`，会从 `SimulationModel.modelMap` 清理，避免残留。

## 5. 运行控制实现

启动：

远程工具会直接创建 `SimulationRunningThread`，并把 `showAnimation` 写到 `SimulationInstance`：

```java
instance.setShowAnimation(showAnimation);
new SimulationRunningThread(instance, 0, 1, null, null, null, null, () -> {
    model.setLocked(previousLocked, true);
    instance.setShowAnimation(previousShowAnimation);
}).start();
```

说明：

- `startRemoteSimulation` 只走纯引擎启动。
- 启动前会做用户/模型校验、运行数量限制、`runId` 生成、参数快照、状态更新、MQTT 事件、结果快照准备。
- 启动前校验包括：未编译的 `ControlMethod`、静态路径 AGVSystem 结构变更都会返回 `SIMULATION_START_FAILED`，不会进入仿真线程。
- 运行准备包括：设置数据记录模式、必要时 reset、运行期间锁定模型、结束后恢复锁定状态和动画状态。
- `showAnimation=false` 用于高速无动画运行；`true` 会启用组件动态绘制和 MQTT JPEG 推帧。
- 启动前生成新的 `runId`。

暂停：

```java
session.model.getDefaultInstance().pause();
```

恢复：

```java
session.model.getDefaultInstance().resume();
```

停止：

```java
synchronized (instance) {
    instance.notify();
}
session.model.stop();
```

重置：

```java
instance.reset();
instance.init();
```

当前 reset 只允许在非 `RUNNING/PAUSED` 状态调用。

## 6. 状态更新来源

状态有两类来源：

1. 工具方法主动更新，例如 start/pause/resume/stop/reset。
2. `SimulationAdapter` 监听器回调更新。

监听的事件：

- `simulationStart`
- `simulationPause`
- `simulationResume`
- `updateTimeDisplay`
- `simulationEnd`

自然结束时：

- 状态更新为 `FINISHED`。
- 记录 `finishedAt`。
- 刷新结果快照。

## 7. 分层结果的当前边界

第一层结果摘要只返回有界数据：

```json
{
  "runId": "运行ID",
  "recordId": "后端模型库ID",
  "modelId": "模型ID",
  "modelFileName": "AGV.fs",
  "status": "FINISHED",
  "simTime": 3600000,
  "startedAt": 1781620000000,
  "finishedAt": 1781620060000,
  "totalOutput": 100,
  "throughputPerHour": 100.0,
  "currentWip": 0,
  "resultStatus": "READY",
  "summaryResults": {
    "taktTime": {},
    "uph": {},
    "utilRate": {},
    "leanMetrics": {},
    "energyAnalysis": {}
  },
  "datasets": [],
  "message": "Simulation finished."
}
```

第二层使用 `getRemoteSimulationResultDatasetPage` 分页读取全量结果，对应这些数据源：

- `PartCycleTimeAnalysisDialog`
- `RBDataDialog`
- `TaktTimeDataDialog`
- `UPHDataDialog`
- `UtilRateDataDialog`
- `WIPDataDialog`
- `LeanMetricsComponent`
- `EnergyAnalysisComponent`

逐件记录、WIP 时间线、Lean LT/换型记录和 Energy 功率曲线不再嵌套进第一层响应。分页接口单页最多 1000 条，只能在本次运行结束后调用。

它仍然不是：

- 全量生产报表
- 全量过程数据导出
- 数据库持久化结果
- 自动报表任务

后续如果要做大屏或过程监控，需要另开过程数据采集和结果存储模块。

## 8. 当前已知限制

### 8.1 MCP Server 仍是当前工程原有实现

当前 MCP Server 是已有手写 HTTP JSON-RPC Server。它已有 API key 机制，但本轮没有重构鉴权。

后续建议：

- API key 从配置读取。
- 不在源码写真实密钥。
- 支持服务端部署配置。
- 明确监听地址和端口暴露策略。

### 8.2 参数名依赖 `-parameters`

`McpToolBridge` 当前用反射参数名生成 MCP schema。

因此已在 `pom.xml` 增加：

```xml
<arg>-parameters</arg>
```

如果部署包不是用该配置重新编译，前端/后端在 `tools/list` 中看到的参数名可能会异常。

### 8.3 全量 Maven 编译当前不干净

执行：

```bash
mvn -q -DskipTests compile
```

当前工程全量编译失败，失败集中在既有源码：

- UI/3D 相关类
- Lombok 生成方法相关类
- `WorkUnit` 方法缺失

本轮新增远程类做过窄编译验证，验证通过。

### 8.4 不支持跨进程恢复

session 存在 Java 内存里。FactorySimulation 程序退出或重启后：

- 已加载模型丢失。
- 正在运行任务丢失。
- `runId` 不可恢复。

### 8.5 不做复杂权限

当前只根据 `userId + modelId` 判断模型是否属于该用户。

`recordId` 只作为后端模型库记录 ID 在响应和 MQTT payload 中透传，不用于定位内存 session。

这不是完整权限系统。正式对外前需要云端后端补：

- 登录态
- 用户组织权限
- 模型文件权限
- 操作审计
- 运行资源配额

## 9. 后续建议拆分

建议后续按以下顺序继续：

1. 后端 REST 封装 MCP 调用。
2. 前端 MVP 页面联调。
3. MCP Server 鉴权配置化。
4. 模型文件列表接口。
5. 运行任务历史和状态持久化。
6. 过程数据采集。
7. 完整结果报表。
8. 远程部署和网络访问加固。

## 10. 对代码理解的核心提醒

这次代码的本质是：

```text
MCP 工具层
  -> RemoteSimulationManager
  -> SimulationModel / SimulationInstance
```

不是：

```text
Vue
  -> AI 助手
  -> LLM
  -> 工具
```

浏览器动画当前采用第一期截图流：

```text
SimulationModel / ObjectGroupComponent
  -> 离屏 Graphics2D 绘制
  -> JPEG
  -> MQTT over WebSocket
```

当前不包含浏览器原生对象渲染、画布内交互编辑和高帧率视频编码。多层模型按活动 `layerId` 单层推送，避免所有子层并行截图。
