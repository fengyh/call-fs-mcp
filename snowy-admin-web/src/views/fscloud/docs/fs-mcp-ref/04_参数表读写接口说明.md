# 远程仿真参数表读写接口说明

日期：2026-06-16

## 1. 设计约定

模型中预制一个名为 `mcp` 或 `MCP` 的普通 `Table`。

`mcp` 表约定：

| 列 | 内容 |
| --- | --- |
| 第 1 列 | 要开放给 Web 端读取和修改的参数表名称 |
| 第 2 列 | 备注信息，可选 |

后端只允许读取和修改 `mcp` 表中列出的参数表，避免 Web 端任意修改模型里的其他表。

## 2. 表数据格式

参数表返回为通用结构：

```json
{
  "tableId": "table-object-id",
  "tableName": "ProcessParams",
  "wholeNo": ".ProcessParams",
  "remark": "工序参数",
  "columnCount": 3,
  "rowCount": 2,
  "columns": [
    {
      "index": 0,
      "name": "Station",
      "type": "String",
      "format": "General",
      "width": 120,
      "indexColumn": false
    }
  ],
  "rows": [
    ["S1", "10", "20"],
    ["S2", "15", "30"]
  ]
}
```

说明：

- `rows` 是二维字符串数组。
- 前端保存整表时，推荐直接把修改后的 `rows` 原样传回。
- 如果只改少量单元格，也可以使用 patches 方式。
- 写回的是模型本体 `Table`，运行中实例不会被半路改动。下一次 `reset/start` 会使用最新参数。

## 3. 新增 MCP 工具

### listRemoteSimulationParameterTables

作用：读取 `mcp` 表清单，告诉前端有哪些参数表可读写。

参数：

```json
{
  "userId": "u001",
  "modelId": "loaded-model-id"
}
```

业务响应 `data` 示例：

```json
{
  "recordId": "backend-model-record-id",
  "modelId": "loaded-model-id",
  "modelFileName": "demo.fs",
  "status": "LOADED",
  "mcpTableName": "mcp",
  "mcpTableFound": true,
  "parameterTables": [
    {
      "rowIndex": 0,
      "tableName": "ProcessParams",
      "remark": "工序参数",
      "exists": true,
      "tableId": "table-object-id",
      "wholeNo": ".ProcessParams",
      "rowCount": 2,
      "columnCount": 3
    }
  ]
}
```

### getRemoteSimulationParameterSnapshot

作用：读取 `mcp` 清单中所有参数表的当前内容。

参数：

```json
{
  "userId": "u001",
  "modelId": "loaded-model-id",
  "runId": ""
}
```

说明：

- `runId` 传空字符串：立即读取当前模型本体参数表，并保存为最新内存快照。
- `runId` 传具体值：读取该次仿真启动时保存的参数快照。
- `startRemoteSimulation` 会在启动前自动保存一次参数快照，并绑定到新的 `runId`。

业务响应 `data` 示例：

```json
{
  "runId": "run-id",
  "recordId": "backend-model-record-id",
  "modelId": "loaded-model-id",
  "modelFileName": "demo.fs",
  "status": "RUNNING",
  "snapshotAt": 1781620000000,
  "mcpTableName": "mcp",
  "mcpTableFound": true,
  "mcpRows": [
    {
      "rowIndex": 0,
      "tableName": "ProcessParams",
      "remark": "工序参数",
      "exists": true,
      "tableId": "table-object-id",
      "wholeNo": ".ProcessParams",
      "rowCount": 2,
      "columnCount": 3
    }
  ],
  "tables": [
    {
      "tableName": "ProcessParams",
      "columns": [],
      "rows": []
    }
  ],
  "missingTables": []
}
```

### updateRemoteSimulationParameterTable

作用：整表覆盖写回某个参数表。

参数：

```json
{
  "userId": "u001",
  "modelId": "loaded-model-id",
  "tableName": "ProcessParams",
  "rowsJson": "[[\"S1\",\"10\",\"20\"],[\"S2\",\"15\",\"30\"]]"
}
```

`rowsJson` 也支持对象数组：

```json
[
  {
    "Station": "S1",
    "ProcessTime": "10",
    "Capacity": "20"
  }
]
```

注意：通过 MCP 调用时，`rowsJson` 参数本身是字符串，所以需要把 JSON 数组序列化成字符串传入。

写入规则：

- `tableName` 必须在 `mcp` 表第一列中。
- 模型处于 `RUNNING` 或 `PAUSED` 时不允许写入。
- 数组行的单元格数量必须等于表的列数。
- 写入后会返回该表最新快照。

### updateRemoteSimulationParameterCells

作用：按单元格补丁写回参数表，适合前端只改了少量格子的场景。

参数：

```json
{
  "userId": "u001",
  "modelId": "loaded-model-id",
  "tableName": "ProcessParams",
  "patchesJson": "[{\"row\":0,\"column\":1,\"value\":\"12\"}]"
}
```

也可以用列名：

```json
{
  "patchesJson": "[{\"row\":0,\"columnName\":\"ProcessTime\",\"value\":\"12\"}]"
}
```

写入规则同整表覆盖接口。

### batchUpdateRemoteSimulationParameterTable

一次原子回写多张参数表，并可选择是否把修改保存到当前加载的 `.fs` 模型文件。

参数：

```text
userId      用户标识
modelId     MCP Server 内存中的模型实例 ID
tablesJson  getRemoteSimulationParameterSnapshot 返回的 data.tables 数组 JSON 字符串
bSaveModel  是否将修改保存到服务器上的 .fs 模型文件
```

`tablesJson` 推荐直接使用参数快照中的 `data.tables`：

```json
[
  {
    "tableName": "ProcessParameters",
    "columns": [
      {"index": 0, "name": "Process"},
      {"index": 1, "name": "ProcessTime"}
    ],
    "columnCount": 2,
    "rows": [
      ["OP10", "12"],
      ["OP20", "18"]
    ]
  },
  {
    "tableName": "BufferParameters",
    "columns": [
      {"index": 0, "name": "Buffer"},
      {"index": 1, "name": "Capacity"}
    ],
    "columnCount": 2,
    "rows": [
      ["Buffer1", "20"]
    ]
  }
]
```

为了方便后端直接回传查询结果，`tablesJson` 也接受完整的参数快照 `data` 对象，或包含该对象的 `{ "success": true, "data": {...} }` 响应；接口只读取其中的 `tables` 字段，忽略 `runId`、`status`、`snapshotAt` 等只读字段。

MCP `tools/call` 示例：

```json
{
  "jsonrpc": "2.0",
  "id": 21,
  "method": "tools/call",
  "params": {
    "name": "batchUpdateRemoteSimulationParameterTable",
    "arguments": {
      "userId": "user001",
      "modelId": "45e0d208d37c",
      "tablesJson": "[{\"tableName\":\"ProcessParameters\",\"columns\":[{\"index\":0,\"name\":\"Process\"},{\"index\":1,\"name\":\"ProcessTime\"}],\"columnCount\":2,\"rows\":[[\"OP10\",\"12\"]]}]",
      "bSaveModel": false
    }
  }
}
```

成功响应的 `data` 包含：

```json
{
  "recordId": "backend-record-001",
  "modelId": "45e0d208d37c",
  "updatedTableCount": 2,
  "updatedRowCount": 3,
  "tableNames": ["ProcessParameters", "BufferParameters"],
  "bSaveModel": false,
  "modelSaved": false,
  "modelFilePath": null,
  "snapshot": {
    "tables": [
      {"tableName": "ProcessParameters", "rowCount": 2},
      {"tableName": "BufferParameters", "rowCount": 1}
    ]
  }
}
```

`bSaveModel` 规则：

- `false`：只更新当前内存模型，新一轮仿真立即使用新参数；卸载模型或软件重启后修改消失。
- `true`：全部表写入成功后调用模型保存能力，覆盖服务器上当前加载的 `.fs` 文件。
- 保存 `.fs` 文件不会自动更新后端数据库、对象存储或 `recordId` 对应的云端文件。

批量写入规则：

- 所有目标表必须在模型的 `mcp` 表中登记。
- `columns` 和 `columnCount` 只用于校验，不会修改模型表结构。
- 同一个 `tableName` 不能在一次请求中重复出现。
- 系统先校验全部表，全部合法后才开始写入。
- 任意表写入失败或模型保存失败时，已修改的内存表会回滚。
- 模型处于 `RUNNING` 或 `PAUSED` 时禁止写入。
- 成功后向 `factory/sim/{username}/{modelId}/status` 发布 `parameterTablesBatchUpdated` 事件。

MQTT payload 示例：

```json
{
  "username": "user001",
  "recordId": "backend-record-001",
  "modelId": "45e0d208d37c",
  "runId": null,
  "event": "parameterTablesBatchUpdated",
  "timestamp": 1784553000000,
  "status": "LOADED",
  "updatedTableCount": 2,
  "updatedRowCount": 3,
  "tableNames": ["ProcessParameters", "BufferParameters"],
  "bSaveModel": false,
  "modelSaved": false,
  "msgType": "status"
}
```

## 4. 前端推荐流程

1. 后端调用 `loadRemoteSimulationModel` 加载模型，传入后端模型库 `recordId`，拿到 MCP 内存实例 `modelId`。
2. 后端调用 `listRemoteSimulationParameterTables`，确认模型是否配置了 `mcp` 表，以及参数表是否存在。
3. 后端调用 `getRemoteSimulationParameterSnapshot`，把 `columns + rows` 返回给前端表格组件。
4. 前端修改后，后端可调用 `batchUpdateRemoteSimulationParameterTable` 一次回写全部表；少量修改也可继续调用 `updateRemoteSimulationParameterTable` 或 `updateRemoteSimulationParameterCells`。
5. 写回成功后，再调用 `resetRemoteSimulation` 和 `startRemoteSimulation` 开始新一轮仿真。
6. 仿真启动时，系统会自动保存本次 `runId` 对应的参数快照。

## 5. 新增错误码

除已有远程仿真错误码外，参数表接口新增：

```text
PARAMETER_TABLE_NOT_FOUND
MODEL_SAVE_FAILED
```

常见场景：

- 模型里没有 `mcp` 表。
- `mcp` 表第一列没有列出目标参数表。
- `mcp` 表列出的参数表在模型中不存在。

写入运行中模型会返回：

```text
INVALID_STATE
```
